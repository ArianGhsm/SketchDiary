# مستندات پوشه `data`

تمام فایل‌های عملیاتی پروژه باید در این پوشه بمانند.

این قرارداد عمداً سخت‌گیرانه است تا:

- backup ساده بماند
- runtime assetها پراکنده نشوند
- migration پروژه قابل‌مدیریت باشد

---

## فایل‌های مهم

### `students.db`

دیتابیس SQLite پروژه.

داخل این فایل داده‌های اصلی نگه‌داری می‌شوند:

- دانشجوها
- ثبت‌های تاییدشده
- درخواست‌های احراز هویت
- فرم‌ها
- سوال‌ها
- پاسخ‌ها
- زمان‌بندی‌ها

### `default_students.csv`

seed اولیه‌ی دانشجوها.

در startup، اگر جدول دانشجوها خالی باشد، از این فایل import انجام می‌شود.

### `default_verification_photo.png`

تصویر پیش‌فرض کارت احراز هویت.

اگر کاربر عکس پروفایل تلگرام نداشته باشد، این تصویر برای نماینده‌ها ارسال می‌شود.

### `bot.polling.lock`

فایل runtime برای جلوگیری از اجرای هم‌زمان polling روی یک سیستم.

اگر برنامه با crash بسته شده و process دیگری فعال نیست، می‌توان این فایل را حذف کرد.

---

## چه چیزهایی نباید اینجا تغییر کنند

- فایل‌های runtime را به ریشه‌ی پروژه منتقل نکنید
- دیتابیس جدید در مسیر دیگر نسازید
- fallback image را بیرون از `data/` نبرید

---

## نکته‌ی توسعه

اگر feature جدیدی runtime file می‌سازد، به‌صورت پیش‌فرض باید زیر `data/` قرار بگیرد؛ نه در ریشه‌ی مخزن و نه در پوشه‌های دیگر.
