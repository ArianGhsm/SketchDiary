# SketchDiary

ربات تلگرامی دانشجویی با رویکرد **Inline-First** برای مدیریت احراز هویت، نمایش نمره‌ها و ابزارهای نماینده کلاس.

---

## ✨ تصویر کلی

این پروژه یک ربات دانشجویی برای کلاس دندان‌پزشکی ورودی ۱۴۰۲ است که همه‌ی جریان‌های اصلی آن از دکمه‌های اینلاین شروع می‌شوند. متن آزاد فقط در مرحله‌های ورود داده استفاده می‌شود؛ مثل فرستادن شماره دانشجویی، معرفی کوتاه، عنوان فرم، توضیح فرم یا لیست نمره‌ها.

ویژگی مهم نسخه فعلی این است که احراز هویت دیگر مستقیم انجام نمی‌شود. دانشجو درخواست می‌فرستد، نماینده تایید یا رد می‌کند، و نتیجه به‌صورت خودکار به دانشجو برمی‌گردد.

---

## 🚀 قابلیت‌های فعلی

### 👨‍🎓 برای دانشجو

- شروع احراز هویت از منوی اینلاین
- ثبت درخواست احراز هویت با:
  - شماره دانشجویی
  - معرفی کوتاه
  - نام کاربری تلگرام در صورت وجود
- دریافت نتیجه تایید یا رد توسط نماینده
- مشاهده پروفایل تاییدشده
- مشاهده نمره‌ها و تحلیل عملکرد

### 🎓 برای نماینده کلاس

- مشاهده تعداد درخواست‌های احراز هویت در انتظار
- دریافت کارت تایید احراز هویت با دکمه‌های:
  - `✅ تایید حساب`
  - `❌ رد درخواست`
- ثبت گروهی نمره‌ها به‌صورت خط‌به‌خط
- ارسال اطلاعیه همگانی برای دانشجوهای تاییدشده
- ساخت فرم/لیست ثبت‌نام داخلی با:
  - عنوان
  - توضیح
  - مهلت اختیاری
- مشاهده اعضای هر فرم با ترتیب عضویت

### 🛠 برای مدیر

- مشاهده پنل مدیریت
- حذف ثبت فعال دانشجو با شماره دانشجویی
- دسترسی به بررسی درخواست‌ها در صورت قرار داشتن در `ADMIN_IDS`

---

## 🧭 اصول UX پروژه

این مخزن روی چند قرارداد سخت‌گیرانه می‌ایستد:

- ناوبری command-centric پیاده‌سازی نمی‌شود.
- هر قابلیت جدید باید از callback اینلاین شروع شود.
- ورودی متنی فقط برای data-entry مجاز است.
- همه‌ی جریان‌ها باید مسیر `بازگشت` یا `لغو` داشته باشند.
- قبل از تایید هویت، دسترسی کامل به کاربر داده نمی‌شود.
- شناسه‌ها و اطلاعات قابل‌کپی با قالب monospace نمایش داده می‌شوند.
- تاریخ‌ها و زمان‌های کاربرمحور با **جلالی + تهران** نمایش داده می‌شوند.

## 🧩 نقش فایل‌های مهم

| فایل | نقش |
|---|---|
| `main.py` | بوت‌استرپ برنامه، init دیتابیس، seed اولیه و اجرای polling |
| `config.py` | تنظیمات اصلی مثل توکن، شناسه‌ها و مسیر داده‌ها |
| `app_callbacks.py` | مرجع مرکزی همه‌ی `callback_data`ها |
| `db.py` | لایه SQLite برای دانشجوها، ثبت‌ها، درخواست‌های احراز هویت و فرم‌ها |
| `bot/handlers.py` | منطق جریان‌های کاربر، نماینده و مدیر |
| `bot/ui/texts.py` | متن‌های کاربرمحور با قالب HTML |
| `bot/ui/keyboards.py` | کیبوردهای اینلاین |
| `bot/services/datetime_fa.py` | فرمت‌کردن تاریخ/زمان جلالی و تهران |
| `bot/services/formatting.py` | ابزارهای نمایش حرفه‌ای برای داده‌های قابل‌کپی |

## 🔐 جریان احراز هویت جدید

جریان فعلی به این صورت است:

1. دانشجو از منوی اصلی روی `شروع احراز هویت` می‌زند.
2. شماره دانشجویی خود را می‌فرستد.
3. اگر شماره در دیتابیس وجود داشته باشد، یک معرفی کوتاه می‌فرستد.
4. ربات درخواست را برای نماینده یا مدیرهای مجاز ارسال می‌کند.
5. یکی از بررسی‌کننده‌ها درخواست را تایید یا رد می‌کند.
6. نتیجه به‌صورت خودکار به دانشجو ارسال می‌شود.

نکته:
- تایید یک نفر کافی است.
- اگر شماره دانشجویی قبلا روی حساب دیگری فعال باشد، درخواست تایید نمی‌شود.

---

## 📊 نمایش نمره و تحلیل

پس از تایید هویت، کاربر می‌تواند کارنامه‌ی خود را ببیند. گزارش فعلی شامل این موارد است:

- فهرست نمره‌ها
- میانگین شخصی
- رتبه در کلاس
- میانگین کلاس
- فاصله با میانگین کلاس
- دانشجوی برتر کلاس

---

## 🗂 فرم‌ها و لیست‌های ثبت‌نام

نماینده می‌تواند فرم داخلی ساده بسازد. در نسخه فعلی هر فرم این اطلاعات را دارد:

- عنوان
- توضیح
- مهلت اختیاری
- سازنده
- زمان ساخت
- فهرست اعضا بر اساس زمان عضویت

عضویت دانشجو در فرم فقط وقتی مجاز است که:

- احراز هویت او تایید شده باشد
- فرم فعال باشد
- مهلت فرم گذشته نباشد
- قبلا عضو نشده باشد

---

## 🕒 استاندارد تاریخ و زمان

همه‌ی تاریخ‌های کاربرمحور باید با این استاندارد نمایش داده شوند:

- تاریخ جلالی
- منطقه زمانی `Asia/Tehran`
- چیدمان خوانا
- استفاده از `<tg-time ...>` برای زمان‌های مهم

اگر توسعه‌ی جدیدی تاریخ خام میلادی، UTC یا ISO را مستقیما به کاربر نشان بدهد، با قرارداد پروژه ناسازگار است.

## ⚙️ راه‌اندازی

### 1. نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### 2. تنظیم `config.py`

این مقادیر را بررسی یا تکمیل کنید:

- `bot_token`
- `ADMIN_IDS`
- `MAIN_REP_STUDENT_NUMBER`
- `MAIN_REP_TELEGRAM_ID`

### 3. داده‌های اولیه

اگر جدول دانشجوها خالی باشد، برنامه در شروع از فایل زیر seed انجام می‌دهد:

```text
data/default_students.csv
```

در صورت نیاز می‌توانید ایمپورت دستی هم انجام دهید:

```bash
python import_students.py --replace-all
```

### 4. اجرای بات

```bash
python main.py
```

## 🧱 استاندارد توسعه

اگر قابلیت جدیدی اضافه می‌کنید:

- callback جدید را در `app_callbacks.py` تعریف کنید.
- متن‌های کاربرمحور را در `bot/ui/texts.py` نگه دارید.
- کیبوردها را در `bot/ui/keyboards.py` اضافه کنید.
- تاریخ‌ها را فقط از طریق `bot/services/datetime_fa.py` رندر کنید.
- داده‌های قابل‌کپی را با `code(...)` یا helperهای `formatting.py` نمایش دهید.
- مستندات را در همان تغییر به‌روزرسانی کنید.

---

## 🧰 رفع اشکال سریع

### شماره دانشجویی پیدا نمی‌شود

- فایل `data/default_students.csv` را بررسی کنید.
- در صورت نیاز این دستور را اجرا کنید:

```bash
python import_students.py --replace-all
```

### نماینده شناسایی نمی‌شود

- مقدار `MAIN_REP_TELEGRAM_ID` را بررسی کنید.
- مطمئن شوید همان کاربر با `MAIN_REP_STUDENT_NUMBER` تایید شده باشد.

### درخواست احراز هویت برای نماینده ارسال نمی‌شود

- بررسی کنید شناسه نماینده درست باشد.
- اگر از `ADMIN_IDS` برای بررسی استفاده می‌کنید، شناسه‌ها باید عددی و معتبر باشند.
