## معرفی سریع

SketchDiary برای کلاس‌هایی ساخته شده که می‌خواهند چند نیاز رایج را در یک بات جمع کنند:

- احراز هویت دانشجو با تایید نماینده
- نمایش پروفایل و کارنامه
- ساخت فرم و لیست ثبت‌نام شبیه Google Forms
- ساخت سریع لیست فقط با تایید عضویت دانشجو
- محدودیت ظرفیت، Waitlist و جلوگیری از ثبت تکراری
- خروجی متنی، `CSV`، `XLSX` و `JSON`
- تنظیم سراسری کانال‌های اطلاع‌رسانی و جزوه برای کل ربات
- انتشار زمان‌بندی‌شده‌ی فرم در کانال با `APScheduler`
- پنل مدیریت برای مشاهده و غیرفعال‌سازی ثبت‌های فعال و بکاپ دیتابیس

نقطه‌ی تمایز پروژه، **Inline-First UX** است:

- شروع هر قابلیت جدید از دکمه‌های اینلاین انجام می‌شود
- ورودی متنی فقط برای مرحله‌های data-entry است
- در flowها همیشه `بازگشت` یا `لغو` وجود دارد
- قبل از احراز هویت، دسترسی کامل به قابلیت‌های دانشجویی داده نمی‌شود

## قابلیت‌ها

### 🔐 احراز هویت دانشجو

- شروع احراز هویت از منوی اینلاین
- دریافت شماره دانشجویی و معرفی کوتاه
- شروع flow با یک پیام واحد و روشن
- ساخت رکورد `verification_requests`
- ارسال کارت بررسی برای همه‌ی نماینده‌ها و مدیرها
- نمایش عکس پروفایل دانشجو در صورت وجود
- نمایش تصویر پیش‌فرض کلاس از فایل `data/default_verification_photo.png` اگر عکس پروفایل موجود نباشد
- تایید یا رد با دکمه‌های سبز/قرمز
- کافی بودن تایید یک نماینده
- تایید idempotent و بدون خطای `UNIQUE` برای کاربرانی که قبلا سابقه ثبت داشته‌اند
- ارسال نتیجه‌ی نهایی به دانشجو

### 🧾 فرم و لیست ثبت‌نام

- ساخت فرم سفارشی توسط نماینده از پنل اینلاین
- ساخت سریع لیست بدون سوال اضافه؛ دانشجو فقط عضویت خود را تایید می‌کند
- پشتیبانی از این نوع سوال‌ها:
  - متن کوتاه
  - متن بلند
  - عدد
  - تک‌گزینه‌ای
  - چندگزینه‌ای
  - منوی کشویی
  - تاریخ/زمان
- مهلت اختیاری
- ظرفیت اختیاری
- Waitlist
- لینک اشتراک یکتا
- دکمه‌ی ورود و کپی لینک فرم از داخل پنل مدیریت فرم
- انتخاب کانال انتشار هر فرم از بین کانال‌های سراسری ذخیره‌شده

### 👨‍🎓 ثبت‌نام دانشجو در فرم

- ورود با لینک اختصاصی `start=form_<token>`
- نیاز به احراز هویت پیش از ثبت پاسخ
- جلوگیری از ثبت دوباره
- ذخیره‌ی ترتیب ثبت (`registration_order`)
- ذخیره‌ی زمان ثبت و وضعیت:
  - `submitted`
  - `waitlist`
  - `removed`

### 📦 مدیریت فرم برای نماینده

- مشاهده‌ی جزئیات فرم
- مشاهده‌ی آمار ثبت‌نام
- خروجی متنی فقط نام‌ها بدون زمان
- خروجی متنی نام و شماره دانشجویی بدون زمان
- خروجی `CSV`
- خروجی `XLSX`
- خروجی `JSON`
- جست‌وجوی پاسخ‌ها
- افزودن دستی دانشجو
- حذف ثبت دانشجو
- کپی ساختار فرم
- تعیین کانال انتشار فرم از بین کانال‌های سراسری
- بستن و بازگشایی فرم
- حذف کامل فرم با تایید نهایی
- ارسال یادآوری به دانشجوهایی که هنوز ثبت‌نام نکرده‌اند

### ⏰ زمان‌بندی انتشار

- ساخت زمان‌بندی برای انتشار فرم در کانال
- استفاده از کانال انتخاب‌شده‌ی فرم
- اگر فقط یک کانال سراسری ثبت شده باشد، همان کانال به‌صورت خودکار برای فرم استفاده می‌شود
- ثبت زمان انتشار
- ثبت مهلت فرم منتشرشده
- پشتیبانی از:
  - یک‌بار
  - هفتگی
  - ماهانه
- انتشار خودکار فرم در کانال همراه با دکمه‌ی ورود و دکمه‌ی کپی لینک
- مشاهده و غیرفعال‌سازی زمان‌بندی‌های ثبت‌شده

### 📊 کارنامه و تحلیل

- ثبت گروهی نمره‌ها توسط نماینده
- نگهداری نمره‌ها در `student_grades`
- نمایش نمره‌ها برای دانشجو
- تحلیل میانگین، رتبه، میانگین کلاس و فاصله از میانگین

### 🛠 امکانات مدیر

- پنل مدیریت اینلاین
- تنظیم کانال‌های سراسری ربات:
  - کانال اطلاع‌رسانی
  - کانال جزوه
- مشاهده‌ی فهرست دانشجوهای تاییدشده به‌صورت صفحه‌بندی‌شده
- مشاهده‌ی ثبت‌های اخیر
- غیرفعال‌سازی ثبت فعال از طریق:
  - انتخاب دانشجو از فهرست
  - ارسال مستقیم شماره دانشجویی
- ارسال بکاپ ZIP از دیتابیس ربات در تلگرام
- تایید نهایی حذف با دکمه‌ی خطر

## جریان‌های اصلی

### 1. احراز هویت

1. دانشجو روی `شروع احراز هویت` می‌زند.
2. شماره دانشجویی را ارسال می‌کند.
3. معرفی کوتاه خود را می‌فرستد.
4. رکورد درخواست ساخته می‌شود.
5. کارت بررسی برای نماینده‌ها/مدیرها ارسال می‌شود.
6. یکی از بررسی‌کننده‌ها درخواست را تایید یا رد می‌کند.
7. نتیجه به‌صورت خودکار به دانشجو برمی‌گردد.

### 2. ساخت فرم

1. نماینده وارد پنل نماینده می‌شود.
2. روی `فرم سفارشی` یا `ساخت سریع لیست` می‌زند.
3. عنوان، توضیح، مهلت، ظرفیت و وضعیت Waitlist را ثبت می‌کند.
4. در فرم سفارشی، سوال‌ها را یکی‌یکی تعریف می‌کند.
5. در فرم سریع، فرم بدون سوال اضافه و فقط برای جمع‌کردن لیست ساخته می‌شود.
6. برای هر فرم، مقصد انتشار از بین کانال‌های سراسری انتخاب می‌شود.

### 3. ثبت پاسخ فرم

1. دانشجو لینک فرم را باز می‌کند.
2. در صورت تاییدشدن، وارد flow پاسخ‌گویی می‌شود.
3. پاسخ‌ها ذخیره می‌شوند.
4. نتیجه با وضعیت `ثبت‌شده` یا `لیست انتظار` برمی‌گردد.

### 4. زمان‌بندی انتشار در کانال

1. نماینده برای یک فرم، زمان‌بندی می‌سازد.
2. اگر مقصد انتشار فرم از قبل تعیین نشده باشد:
   - در صورت وجود فقط یک کانال سراسری، همان کانال خودکار انتخاب می‌شود
   - در صورت وجود چند کانال، نماینده یکی را برای همان فرم انتخاب می‌کند
3. زمان انتشار، مهلت و تکرار ثبت می‌شود.
4. job در `APScheduler` ذخیره می‌شود.
5. در زمان مقرر:
   - یک نسخه‌ی جدید از فرم ساخته می‌شود
   - فرم در وضعیت `open` قرار می‌گیرد
   - پیام اعلان در کانال ارسال می‌شود

## استانداردهای UX و زمان

### Inline-First

- ناوبری command-centric در این مخزن مجاز نیست
- شروع قابلیت‌ها از callbackهای اینلاین انجام می‌شود
- متن آزاد فقط برای ورود داده مجاز است

### نمایش داده‌های قابل کپی

- شماره دانشجویی با `monospace`
- آیدی عددی تلگرام با `monospace`
- یوزرنیم در صورت نیاز با `monospace`
- لینک‌ها و توکن‌ها به‌صورت copy-friendly

### دکمه‌های رنگی

در پروژه از `InlineKeyboardButton.style` استفاده می‌شود:

- `success` برای تایید/ادامه/شروع
- `danger` برای حذف/رد/لغو
- اکشن‌های خنثی و ناوبری به‌صورت پیش‌فرض بی‌رنگ می‌مانند تا فقط تایید و خطر برجسته شوند

### تاریخ و زمان

تمام زمان‌های کاربرمحور باید:

- به تقویم جلالی نمایش داده شوند
- بر اساس `Asia/Tehran` باشند
- برای زمان‌های مهم با `<tg-time unix="...">...</tg-time>` رندر شوند

نمونه‌ها:

- زمان تایید احراز هویت
- مهلت فرم
- زمان انتشار
- زمان ثبت پاسخ

## نصب و راه‌اندازی

### پیش‌نیازها

- Python 3.11+ یا جدیدتر
- دسترسی به Bot Token تلگرام
- فایل `data/default_students.csv` با ستون‌های معتبر

### 1. نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### 2. تنظیم hook محلی

```bash
git config core.hooksPath .githooks
```

### 3. پیکربندی

این پروژه فعلاً از فایل `config.py` استفاده می‌کند و `.env` ندارد.

مقادیر مهم:

| متغیر | توضیح |
| --- | --- |
| `bot_token` | توکن ربات تلگرام |
| `ADMIN_IDS` | شناسه‌های مدیر |
| `MAIN_REP_STUDENT_NUMBER` | شماره دانشجویی نماینده اصلی |
| `MAIN_REP_TELEGRAM_ID` | آیدی تلگرام نماینده اصلی |
| `DB_PATH` | مسیر دیتابیس SQLite |
| `DEFAULT_STUDENTS_CSV` | مسیر فایل اولیه دانشجوها |
| `DEFAULT_VERIFICATION_PHOTO_PATH` | تصویر پیش‌فرض کارت احراز هویت |

### 4. آماده‌سازی داده‌های اولیه

اگر جدول دانشجوها خالی باشد، برنامه در startup تلاش می‌کند از فایل زیر seed انجام دهد:

```text
data/default_students.csv
```

برای import دستی:

```bash
python import_students.py --replace-all
```

### 5. اجرای بات

```bash
python main.py
```

## پیکربندی

### فایل `config.py`

پروژه به‌جای env از مقداردهی مستقیم در `config.py` استفاده می‌کند. اگر بخواهید آن را برای deploy واقعی سخت‌تر کنید، بهتر است بعداً به `.env` مهاجرت دهید، اما وضعیت فعلی مخزن این است:

- تنظیمات پروژه در فایل Python
- ساخت خودکار پوشه‌ی `data/`
- ذخیره‌ی همه‌ی فایل‌های عملیاتی زیر همین پوشه

### نیازمندی‌های runtime

- ربات باید در کانال موردنظر دسترسی ارسال پیام داشته باشد
- برای کانال‌های سراسری، شناسه کانال باید معتبر باشد
- برای نمایش fallback تصویر، فایل `data/default_verification_photo.png` باید موجود بماند

## خروجی‌ها و گزارش‌ها

### خروجی متنی داخل تلگرام

- فقط نام‌ها
- نام + شماره دانشجویی

### فایل‌های خروجی

- `CSV`
- `XLSX`
- `JSON`

در خروجی‌های فایل، علاوه بر ستون‌های اصلی دانشجو:

- زمان ثبت به‌صورت فارسی (`submitted_at_fa`)
- زمان ثبت به‌صورت یونیكس (`submitted_at_unix`)
- وضعیت فارسی ثبت
- پاسخ هر سؤال در ستون‌های مستقل

این ساختار باعث می‌شود خروجی‌ها هم برای خواندن دستی مناسب باشند و هم برای پردازش بعدی.

## رفع اشکال سریع

### خطای `TelegramConflictError`

این خطا یعنی بیش از یک process برای همین bot token در حال `getUpdates` است.

راه‌حل:

- فقط یک نمونه از بات را اجرا کنید
- اگر بات روی سیستم یا سرور دیگری روشن است، آن را متوقف کنید
- اگر process دیگری وجود ندارد ولی فایل قفل مانده، `data/bot.polling.lock` را حذف و دوباره اجرا کنید

### دانشجو در seed پیدا نمی‌شود

```bash
python import_students.py --replace-all
```

و بعد `data/default_students.csv` را از نظر ستون `studentid` و نام بررسی کنید.

### زمان‌بندی اجرا نمی‌شود

- مطمئن شوید حداقل یک کانال سراسری معتبر برای ربات ثبت شده باشد
- اگر برای فرم بیش از یک کانال سراسری موجود است، مقصد انتشار فرم را انتخاب کنید
- مطمئن شوید ربات در کانال مقصد دسترسی ارسال پیام دارد
- قالب زمان را به‌شکل `YYYY/MM/DD HH:MM` ارسال کنید

### ثبت فرم انجام نمی‌شود

- مطمئن شوید کاربر احراز هویت شده است
- وضعیت فرم باید `open` باشد
- اگر ظرفیت پر شده و Waitlist خاموش باشد، ثبت جدید انجام نمی‌شود

## توسعه و مشارکت

### Definition of Done

هر تغییر باید این موارد را رعایت کند:

- Inline-First را نشکند
- Auth-First را حفظ کند

- `README.md` را هم‌زمان با تغییر کد به‌روز کند

### بررسی پیش از تحویل

```bash
python -m compileall main.py bot db.py config.py app_callbacks.py
python tools/check_readme_sync.py
```
