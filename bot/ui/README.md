# مستندات پوشه `bot/ui`

این پوشه لایه‌ی نمایش پروژه است: متن‌های HTML و کیبوردهای اینلاین باید اینجا متمرکز بمانند تا flowها در `handlers.py` شلوغ و تکراری نشوند.

---

## فایل‌ها

### `texts.py`

مسئول متن‌های کاربرمحور:

- متن‌های فارسی و polished
- info cardها و layoutهای خوانا
- نمایش داده‌های قابل‌کپی با `monospace`
- رندر زمان با helperهای مشترک
- متن picker تاریخ/زمان

### `keyboards.py`

مسئول دکمه‌ها و keyboardهای reusable:

- keyboard factory مرکزی
- دکمه‌های رنگی با `style`
- دکمه‌های `copy_text`
- actionهای open/copy برای لینک‌ها
- pagination
- تایید حذف و اکشن‌های خطرناک
- picker تاریخ/زمان

---

## قراردادهای UI

### Button-First

- هر جا انتخاب از بین مقادیر شناخته‌شده ممکن است، از دکمه استفاده کن
- تایپ آزاد فقط برای data-entryهای واقعاً لازم بماند
- برای datasetهای بزرگ از pagination و search-result selection استفاده کن

### Button Semantics

- `success` برای تایید، ادامه، شروع و ذخیره
- `danger` برای حذف، رد، لغو و بستن
- `primary` برای ناوبری، مشاهده و انتخاب‌های خنثی

### Copy-Friendly Data

این موارد باید در UI تمیز و قابل‌کپی نمایش داده شوند:

- شماره دانشجویی
- شناسه‌های داخلی
- لینک فرم
- token و code
- شناسه‌ی کانال

### Date/Time UX

برای انتخاب تاریخ/زمان از component مشترک استفاده می‌شود و مسیر پیش‌فرض آن این است:

1. انتخاب سال
2. انتخاب ماه
3. انتخاب روز
4. انتخاب ساعت
5. انتخاب دقیقه
6. تایید نهایی

قواعد:

- تاریخ‌ها جلالی باشند
- timezone تهران حفظ شود
- امروز، پاک‌کردن و بازگشت مرحله‌ای وجود داشته باشد
- از تایپ خام تاریخ/زمان تا جای ممکن پرهیز شود

---

## وقتی UI جدید اضافه می‌کنی

1. متن را در `texts.py` بساز.
2. keyboard را در `keyboards.py` اضافه کن.
3. اگر pattern تکرارشونده است، آن را reusable نگه دار.
4. اگر لینک/توکن/کد تولید می‌شود، action مناسب مثل open/copy هم اضافه کن.
5. اگر flow خطرناک است، تایید نهایی با دکمه‌ی `danger` فراموش نشود.
